## about

I'm Abdullah.

Most of my technical work lives somewhere between cloud infrastructure,
automation, and the awkward moment between **"it deployed"** and
**"it actually behaves the way I expected."**

I like building things that are repeatable, breaking them on purpose,
and figuring out what really happened instead of stopping at
_"well... it works now."_

Security tends to follow me into most of what I build too.
Not as a final checklist — more as part of how I think about the system.

Right now, I'm spending more time on the fundamentals behind the tools:
**Linux, networking, troubleshooting, and systems thinking.**

## things I've built

### Multi-Cloud Failover

**AWS · Azure · Terraform · Cloudflare**

I wanted to see what happens when the place serving your application
simply disappears.

So I built a small multi-cloud setup around health checks and automated
failover between AWS and Azure.

The interesting part wasn't just making failover happen.
It was seeing the extra complexity that comes with trying to make
two cloud environments behave like one resilient system.

[**explore the repo →**](https://github.com/NVX-11/multi-cloud-failover)

---

### DevOps Microservices Platform

**Kubernetes · GitOps · Observability · Security**

This became my playground for putting several DevOps pieces together
instead of learning each one in isolation.

Containers, Kubernetes, GitOps, monitoring, secrets and policies all
had to live in the same place — which is where things became much more
interesting than a simple deployment.

[**explore the repo →**](https://github.com/NVX-11/DevOps-Project)

---

### Serverless Task API

**Lambda · API Gateway · DynamoDB · Terraform**

The API itself was intentionally simple.

The useful part for me was everything around it:
building the infrastructure as code, connecting managed AWS services,
and thinking about what you gain — and give up — when there are
basically no servers left for you to manage.

[**explore the repo →**](https://github.com/NVX-11/serverless-task-api)
